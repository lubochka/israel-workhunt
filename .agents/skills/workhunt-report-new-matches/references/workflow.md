# Report new matches workflow

Reconcile final IDs with both canonical histories. Count only distinct qualified-new opportunities, excluding admission pages, seller listings, suppressions, prior reports and unresolved duplicates. Show exact title/ID, listing and response URL/navigation, city/country, work mode, country eligibility, fit M/N/percentage/gaps, qualifying publication/refresh and route-check time. State actual count and shortfall against the requested minimum without weakening gates. Use the configured output language. In a requested CV-fit reassessment, show every above-threshold opportunity and its separate remaining shortlist blocker. Write requested platform-specific drafts using supported facts only and label `Draft — not sent`; do not invent attachments, rates, availability or fields. Absent message fields and login-hidden fields must be described accurately. Excluded/stale recommendations get no letter unless separately requested as clarification outside the count. An established authorized notification run can be silent at zero; a manual search receives an honest result. Cards belong in the requested chat, with JSON secondary. No application or external delivery is implied.

Read the current private `work_location_policy` separately from saved freshness: explicit `base_country`, `work_path`, selected `exclude_required_foreign_conditions` and `unknown_eligibility` handling. Unconfigured policy has no country fallback. Eligibility evidence must match both country and path, pair the exact opportunity ID and listing URL, record an aware nonfuture observation and review the full ad or a verified form linked from that listing. Required conflicting foreign conditions exclude; absent, ambiguous or contradictory evidence cannot qualify. Optional alternatives remain separate, and travel uncertainty does not imply a visa requirement. Publisher nationality, remote/sponsorship labels and CV location establish neither citizenship/permits nor eligibility. Full-ad absence of a requirement is limited evidence, not employer confirmation or legal clearance. Apply current preferences in scan, render and packets, including saved run-ID and copied-brief requests, while preserving historical windows, minimums, source policy and saved decisions. Store actual policy provenance and eligibility assessments only in private records, packets and pages.

Keep employment `required_stack` separate from explicitly confirmed client-project alternatives in `search_brief.project_stack_policy`. The empty shared policy enables none; CV technologies never adopt preferences. Search each selected project capability and client-outcome term independently of employment combinations. Generic titles and incomplete descriptions may be provisional leads, but alternate-stack qualification needs paid buyer deliverables, matching configured capability keys and exact listing evidence. Only actual buyer requirements enter the unchanged 75% score, including backend gaps. Preserve every independent eligibility, degree, freshness, route and history gate. Hidden buyer names remain unknown when an exact project ID identifies the brief. Saved project policies, including absence, never inherit today's choices.

For an explicit manual report, show new promising projects within the selected policy with evidenced fit of at least 75% but unresolved independent checks as separate unverified notes: score/gaps, exact link, missing evidence and next check. They count zero qualified matches and receive no recommendation letter. This does not add a renderer feature, change notification silence or create an alert.
