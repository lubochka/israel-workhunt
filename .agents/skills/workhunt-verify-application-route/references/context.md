# Shared Workhunt context

This release has no candidate profile. Read `.workhunt/profile.json` and `.workhunt/profile-evidence.json` in the user's explicitly selected workspace. Use the `workhunt-configure-profile` skill if they are absent or unconfigured. Unknown facts and preferences block dependent actions only; do not infer them from examples.

[The playbook](playbook.md) and [tracking contract](tracking.md) apply to all focused skills. Preserve the exact 75% fit calculation, fixed publication/refresh bounds (both run type and context manual: saved source-evidenced windows; collector, notification, assessment and fixture: exactly 24 hours), route identity, country eligibility, history and submission evidence. Result language and candidate criteria come from private settings. The current request controls scope and destination; shared guidance is not authorization to act externally.

Keep actual CVs, extracts, completed drafts and history out of provider packages. Sources are public read-only tools or isolated hidden/headless sessions; never personal browser profiles or desktop control. Retain factual unknowns and disagreements, and report only observed results.

A copied legacy brief requires unambiguous canonical context recovery; dormant preferences never activate merely by loading history. Preserve unresolved context and original base bounds privately when evidence conflicts or is absent.

Read the current private `work_location_policy` separately from saved freshness: explicit `base_country`, `work_path`, selected `exclude_required_foreign_conditions` and `unknown_eligibility` handling. Unconfigured policy has no country fallback. Eligibility evidence must match both country and path, pair the exact opportunity ID and listing URL, record an aware nonfuture observation and review the full ad or a verified form linked from that listing. Required conflicting foreign conditions exclude; absent, ambiguous or contradictory evidence cannot qualify. Optional alternatives remain separate, and travel uncertainty does not imply a visa requirement. Publisher nationality, remote/sponsorship labels and CV location establish neither citizenship/permits nor eligibility. Full-ad absence of a requirement is limited evidence, not employer confirmation or legal clearance. Apply current preferences in scan, render and packets, including saved run-ID and copied-brief requests, while preserving historical windows, minimums, source policy and saved decisions. Store actual policy provenance and eligibility assessments only in private records, packets and pages.

The maintained opportunity catalog now has 28 entries, preserving the original 23 identities and evidence. Arc, HN, Scalable Path, X-Team and Gun.io are manual routes; Guru retains its historical API-documentation 403 alongside scoped project/quote observations. Public source pages are not verified opportunities. The 288-board employer snapshot and shared seed remain unchanged.

Resolve the current explicit request into one complete brief with fixed anchor/windows, minimum/cap and source selection. That resolved brief governs the run; configured preferences fill unspecified new-run settings only. Saved bounds, collector isolation and current private location checks retain their separate contracts. Attaching or reviewing the generic search-request template never invokes it.
