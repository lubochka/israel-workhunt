# Check freshness workflow

For manual research, read the private `search_brief.manual_source_freshness_hours` and `manual_freshness_policy`. Their shared defaults are empty. Use one fixed run anchor and subtract elapsed durations in the configured time zone. A source-specific extension needs explicit user policy and evidence that the exact opportunity belongs to that source group; unsupported membership or a cross-post alone cannot obtain a wider window. Use the standard 24-hour window when no supported exception applies. Preserve historical bounds and requested minimums without retroactive changes. Automated collector qualification and notifications still require exactly 24 hours; manual policy does not change that code or authorize execution. Record original publication, update/repost, feed/alert availability, first discovery, deadline and verification as distinct events with raw text, source URL and precision. Original publication OR a genuine evidenced refresh/repost inside the window can qualify. An older original date does not cancel a recent valid refresh. Discovery/crawl/check time and malformed relative labels do not qualify. Date-only or relative evidence needs its whole supported interval inside the window; never invent an hour. Preserve contradictory or future-dated evidence as unresolved. Source-specific semantics apply only to the observed channel. Reposts retain identity and exclusions. A proposed check is not a live observation; no schedule or API run is implicit.
