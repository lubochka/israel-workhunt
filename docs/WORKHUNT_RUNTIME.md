# Local runtime contract

Resolve shared templates and source registries independently of private setup. The private root is `.workhunt` below the explicitly selected working directory. The configure-profile skill initializes before any profile exists; unknown preferences keep scanning disabled. Collector and renderer settings come from that private profile.

The collector requires an explicit offline fixture or authorized network mode. It bounds responses, retains pagination/partial-fetch evidence and keeps all discoveries in private run snapshots. Only relevant or already-known identities merge into canonical `data/jobs.json`; connected aliases retain provenance and suppression/reporting/submission state. Canonical review overrides legacy review inputs. Changed preferred source IDs linked by aliases do not establish disappearance. Read-only legacy inputs are never output targets. Complete explicit alias bridges persist through merge and reload. SmartRecruiters malformed detail fields are record-local partial evidence; valid peers and safe facts from the same posting survive, while mismatched detail IDs supply no facts.

The shared qualifier counts distinct requirements once, accepts exactly 75%, and requires explicit acceptance/evidence for listed alternatives. Degree policy, skill-duration constraints, geography, route identity, fixed freshness bounds and history remain separate gates. Saved runs retain their own bounds and counts; newly derived counts are labeled separately. Saved notes do not grant authorized methods/actions. The shared qualifier applies source-specific windows only when both `run_type` and `execution_context` are `manual`. Read the private `search_brief.manual_source_freshness_hours` and optional `manual_freshness_policy`; shared defaults are empty. At a new run, fix one anchor instant, subtract elapsed hours in UTC and express bounds in the configured IANA time zone, including clock changes. Save the bounds, time zone, source windows, policy and requested minimum together. A configured `employer_registry` or `techmap` exception requires the exact opportunity ID and listing URL paired in one identity or explicit alias, a public provenance URL, textual membership evidence and an aware, nonfuture observation time. A later membership observation does not move the publication anchor. Unsupported membership falls back to that saved run's `other` window, normally 24 hours for a new run; discovery/feed update times and a cross-post alone do not prove membership or freshness. Saved bounds and policy remain authoritative when the current profile changes. Collector, notification, assessment and fixture contexts always use exactly 24 elapsed hours, including legacy scan runs. Settings do not authorize execution.

`packets.py prepare WORKSPACE --input request.json --output packets/draft.json` prepares an unsent local artifact. Input/output paths are absolute private paths or relative to `.workhunt`. Only explicit `--save-canonical` adds the prepared packet to its exact existing opportunity. Canonical/configuration/legacy files cannot be artifact outputs. `record-event` records supplied evidence and authorization; it is not a transport and cannot submit.

The private profile's `cv_manifest` pointer controls exact language/role selection. Missing, ambiguous, changed, unreviewed or unresolved versions cannot be ready to attach. A content review references the exact file hash and actual evidence; hashing alone is not review. External sending still requires separate direct authorization.

`outcomes.py WORKSPACE --output reports/outcomes.md` writes private Markdown and JSON after preflighting both destinations. It uses the configured time zone and reports historical saved evidence, never new freshness/route verification. Unique identities are separate from per-source overlap counts; prepared, uploaded, observed submitted, user-reported and receipt evidence remain distinct. Latest displayed event does not erase ever-applied history; ever-reported, applied and suppressed metrics are independent. Shared route normalization accepts recorded legacy exact-listing fields, but current qualification still requires exact linkage, evidence and recency. The renderer writes UTF-8/LF bytes reproducibly.

See [employer source maintenance](../sources/EMPLOYER_SOURCES.md) for the pinned 288-board seed, private overrides and observed-health semantics, and [placement](skills/SOURCE_AND_PLACEMENT_MAP.md) for portable installed packages.

Renderer and packet preparation share canonical run selection: an explicit `search_run_id`, otherwise the active run, otherwise the latest saved run. A packet request may instead supply one full `search_brief` snapshot with aware, non-null `window_start` and `window_end`; never combine the two selectors. Preserve the saved source windows, policy and requested minimum. Invalid or empty snapshots fail rather than deriving a sliding window. Only when no saved run or explicit snapshot exists may current profile settings create a new brief. The resulting brief is stored privately with the packet. Renderer-derived counts stay separate from the selected run's saved count.
