## Bounded recovery from access failures

Consult ordered documented employer manual routes before default ATS landings and prefer the recorded working URL/method. Record URL, method, observation time, query/category/page scope and actual failure. Attempt identity is the functional URL plus `public_page`, `isolated_browser` or `public_search`, preserving `embed`, `ashby_jid`, requisition parameters and observed redirect targets. Recognized tracking parameters do not create a new route. Legacy `attempted_urls` means `public_page` only; structured `attempted_routes` requires an explicit method. A failed extractor does not consume an unattempted browser route.

For a shell or loading page, allow one readiness wait of at most 20 seconds and at most two additional content reads. Require actual role/detail evidence for each employer. A corporate homepage, blank iframe or one mixed-employer query is not coverage. Continue pagination on an evidenced nonempty partial list; completed `checked` or `checked_empty` scopes receive no failure fallback. On actual failure, try at most three unique remaining documented URL/method pairs once. If those fail, an authorized manual search may use bounded per-employer exact original-ad/requisition discovery with its own evidence, then retain the limitation and continue elsewhere. Do not loop corporate page to the same failed iframe and back. Respect access controls, rate limits and authentication; never use personal cookies, credentials or guessed private endpoints. The helper plans offline and does not execute these reads.

`checked_empty` requires an explicit empty message for the selected completed scope, with no contrary observed roles and no remaining pages. A successful HTTP response, `Total lines: N`, JavaScript shell, blank iframe, generic login, category-specific empty message or 403/404 does not establish zero jobs. Store `observed_count` separately from coverage completeness. Source-page recovery does not prove any exact vacancy, application form, freshness or fit and never updates collector health.

## Bind observations to their target

Bind evidence before completion, pagination or consumed-attempt decisions. Supply `target_id` (canonical ID or documented alias), actual `source_url`, method, nonblank textual evidence and bounded scope/count fields. Legacy `source_id`, `source`, `employer_id` and `employer` remain accepted only when every supplied identity resolves uniquely and agrees. Without explicit identity, a unique exact configured route or exact catalog website can bind. Website-only original sources retain that exact navigation anchor. Hosts, URL prefixes, shared ATS pages and query variants are not ownership; functional parameters remain significant.

An unconfigured detail URL requires explicit identity plus `navigation: {from_url, to_url, evidence}`, pairing its configured route/catalog website with the observed URL and nonblank navigation evidence. Conflicting or ambiguous identity, route or redirect stays `not_attempted`, preserving applicable routes and diagnostics. Each attempt is independently bound after its parent observation. Foreign malformed attempts stay diagnostic; bound own attempts still require a supported explicit method. Full catalog, lifecycle and employer targets, including unselected ones, participate in ambiguity checks. This checks supplied structure, not factual truth or authorization.

The CLI accepts one private observation or `{"observations": [...]}` and returns `coverage` and `fallbacks` keyed by target ID. Supply one bounded observation per target. Duplicate candidate observations for the same target are rejected rather than selecting a winner or merging categories. A completed page/query/category is not whole-board coverage. Shared-root resolution and current private applicability remain separate from observation input; the latter must stay under `.workhunt`.

`binding`, `ignored_observation`, `ignored_attempts` and `other_observations` can retain supplied private payloads. Keep every filled diagnostic private, including renamed/nested JSON reports. The exporter rejects observation-binding artifact names and these diagnostic fields recursively in distributed JSON. Generic Python test fixtures and this schema explanation are not completed user records.
