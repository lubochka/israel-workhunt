# Optional local runtime

`scripts/scan.py WORKSPACE --fixtures FILE` is an offline adapter exercise. `--network` is a separate explicit opt-in for an authorized public search. Both require a valid private profile, and all generated runs remain under `.workhunt/`. An unconfigured profile, missing capability/location patterns or match-all patterns fail before requests. Sources are disabled by default. Profile-filled snapshots are private.

`scripts/render.py WORKSPACE [--fixture]` reads canonical private records and current gates. Any explicit `--output` must remain under `.workhunt/`. The board embeds local data without remote assets; neither the renderer nor its UI sends applications. Keep the page private.

The 75% score uses distinct required criteria and exact fractions. Qualification independently checks full description, role, capability evidence, confirmed eligible-from country, degree evidence, a current exact route, supported publication/refresh evidence within the applicable saved window and known history. Generic login and email-only routes fail. Preserved historical decisions are not current verification. Missing sources or partial scans do not establish closure.

`tools/maintain_workhunt_sources.py` imports a reviewed snapshot only with explicit `--apply`, to private `.workhunt/sources/`. Network download requires `--network`; it does not scan employers. `tools/probe_workhunt_apis.py` requires `--network`, validates the private profile and writes private health evidence. Imports do not run probes automatically.

The shared seed contains 288 pinned public employer boards; private overrides and observed health remain separate. Disabled overrides win over rediscovery. Missing upstream never means a closed employer, and a later failure retains prior successful-check evidence. Explicit Techmap selection supports 19 feeds whose title-only records stay provisional.

Connected identity aliases merge cross-source discoveries without losing provenance. All discoveries remain in private snapshots, while only relevant or already-known identities enter canonical history. Saved run bounds/counts remain separate from current derived counts and canonical review wins over legacy input.

`scripts/packets.py prepare WORKSPACE --input request.json --output packets/draft.json` emits a private unsent artifact. Only `--save-canonical` writes that preparation into its existing opportunity. `record-event` records supplied evidence and never sends. The private profile's `cv_manifest` pointer selects exactly one current language/role version; missing, changed, ambiguous, unreviewed or unresolved CVs are not ready to attach. Hash equality alone is not content review. Submission events/snapshots are append-only; a later upload never retracts prior valid application evidence, and full identity aliases persist through save/reload.

`scripts/outcomes.py WORKSPACE --output reports/outcomes.md` uses the configured time zone and preflights both private Markdown/JSON outputs. Saved historical evidence is not a fresh check. Unique identities and overlapping per-source counts are distinct; preparation, upload, user report, observed submission and receipt remain separate. Artifact outputs cannot overwrite canonical/configuration or legacy inputs. Ever-reported, applied and suppression facts are independent. Shared route normalization retains exact-listing evidence; the renderer writes UTF-8/LF. The shared qualifier applies source-specific windows only when both `run_type` and `execution_context` are `manual`. Read the private `search_brief.manual_source_freshness_hours` and optional `manual_freshness_policy`; shared defaults are empty. At a new run, fix one anchor instant, subtract elapsed hours in UTC and express bounds in the configured IANA time zone, including clock changes. Save the bounds, time zone, source windows, policy and requested minimum together. A configured `employer_registry` or `techmap` exception requires the exact opportunity ID and listing URL paired in one identity or explicit alias, a public provenance URL, textual membership evidence and an aware, nonfuture observation time. A later membership observation does not move the publication anchor. Unsupported membership falls back to that saved run's `other` window, normally 24 hours for a new run; discovery/feed update times and a cross-post alone do not prove membership or freshness. Saved bounds and policy remain authoritative when the current profile changes. Collector, notification, assessment and fixture contexts always use exactly 24 elapsed hours, including legacy scan runs. Settings do not authorize execution.

Loading historical data is distinct from creating a new profile brief. Only a new profile brief or a saved snapshot explicitly marked `execution_context: manual` may derive source windows from preferences. For an exact copied legacy brief, recover context only from unambiguous canonical snapshots with consistent context, policy, time zone and bounds. Inferred manual context alone does not activate dormant mappings. Unknown or conflicting manual history stays `unresolved` at its recorded base bounds; supplied source-window evidence is retained separately as `recorded_source_windows`. Keep `context_provenance` and matching run IDs inside private records/packets. Preserve original provenance and `recorded_source_windows` through normalization, JSON save/reload and packet preparation; `context_resolution` describes the current normalization separately. Neither provenance field grants permission or activates preferences. Do not invent manual markers or silently replace contradictory supplied bounds. Explicit collector, notification, assessment and fixture behavior remains 24 hours.

Renderer and packet preparation share canonical run selection: an explicit `search_run_id`, otherwise the active run, otherwise the latest saved run. A packet request may instead supply one full `search_brief` snapshot with aware, non-null `window_start` and `window_end`; never combine the two selectors. Preserve the saved source windows, policy and requested minimum. Invalid or empty snapshots fail rather than deriving a sliding window. Only when no saved run or explicit snapshot exists may current profile settings create a new brief. The resulting brief is stored privately with the packet. Renderer-derived counts stay separate from the selected run's saved count.

The bundled `tests/fixtures/legacy-collector-synthetic.json` regression is hand-authored English synthetic data, not extracted historical profile output. Its tests require neither Git history nor a fixture generator. Real context provenance, matching run IDs and recorded source-window evidence remain private.

Read the current private `work_location_policy` separately from saved freshness: explicit `base_country`, `work_path`, selected `exclude_required_foreign_conditions` and `unknown_eligibility` handling. Unconfigured policy has no country fallback. Eligibility evidence must match both country and path, pair the exact opportunity ID and listing URL, record an aware nonfuture observation and review the full ad or a verified form linked from that listing. Required conflicting foreign conditions exclude; absent, ambiguous or contradictory evidence cannot qualify. Optional alternatives remain separate, and travel uncertainty does not imply a visa requirement. Publisher nationality, remote/sponsorship labels and CV location establish neither citizenship/permits nor eligibility. Full-ad absence of a requirement is limited evidence, not employer confirmation or legal clearance. Apply current preferences in scan, render and packets, including saved run-ID and copied-brief requests, while preserving historical windows, minimums, source policy and saved decisions. Store actual policy provenance and eligibility assessments only in private records, packets and pages.

## Manual planning, recipient drafts and supplied outcomes

Read [manual discovery](MANUAL_DISCOVERY.md) for 28 source entries and scoped historical access evidence. Public catalogs resolve from the shared release root, independently of private `.workhunt` records. An explicit `--shared-root` can select the public catalog for offline planning; outcomes use the same workspace resolver, so missing private catalog copies never silently disable source aliases.

```text
python skills/workhunt-search/scripts/discovery_routes.py WORKSPACE --source Arc --source CodementorX --employer CodeValue
python skills/workhunt-search/scripts/drafts.py WORKSPACE --input requests/draft.json --output drafts/local.json
python skills/workhunt-search/scripts/outcomes.py WORKSPACE --output reports/outcomes.md
```

Planning makes no requests or health writes. Optional `--observation FILE` reads a private supplied coverage record. `checked_empty` requires nonblank explicit empty evidence for a completed bounded scope; shells, blank/login pages and failures stay partial/blocked. Fallbacks contain at most three unique normalized, unattempted documented alternatives, once each. Source aliases unify planning labels only; acquisitions and unselected lifecycle references do not add channels or merge opportunities. HN normalization keeps exact item ID/time, thread identity separately and explicitly evidenced employer aliases; it invents no refresh or full-ad verification.

Read [recipient drafts](../../workhunt-apply/references/recipient-drafts.md). Four recipient/stage contracts preserve supported content, actual recipient, limits, claims, contribution/disclosure and selected-file quality. Private standalone drafts need no configured profile, but their request and all canonical/configuration/legacy/shared inputs are protected from output overwrite. Packet preparation calls the same reviewer. Every draft remains `not_sent`; readiness, qualification, upload, submission and authorization are distinct.

Exact linked project proposal forms may supply eligibility provenance only for projects, with matching ID/client/listing/navigation/evidence/time. Generic intake cannot qualify. A concrete agency vacancy at `agency_screening` retains all ordinary checks. Current private work-location policy and geography still apply independently of saved freshness.

Optional private `search_runs[].source_activity[]` and opportunity `outcome_events[]` carry nonblank string `event_id`, `source`, aware nonfuture `at`, nonblank `evidence`, and a known `kind`. `research_time` records finite nonnegative `seconds`; `proposal_spend` records finite nonnegative actual `amount` and an alphabetic three-letter `currency`. `reply_observed`, `interview_observed` and `paid_engagement_observed` require an identity record. Source attribution must match that identity or carry explicit evidence. Duplicate event IDs count once; conflicting payloads/identities stay unresolved. Malformed entries without usable IDs retain recorded values and collection locations in diagnostics, without invented IDs; valid peers survive. Missing categories remain unknown, currencies stay separate, and no rates, earnings, causal conversion or interest are inferred. Reports retain known unique-identity denominators, saved rejection reasons and per-source overlap, separately from fresh verification.

Scoped historical routes retain their actual observed URLs. Arc's Israel-filtered page has `eligible_countries_any: [IL]`; Scalable Path's .NET page has `required_stack_any: [dotnet, .net]`. Offline catalog inspection returns these references with `applicability_check` as applicable, inapplicable or unknown. Only an explicitly configured profile with matching `eligible_countries` or `search_brief.required_stack` makes that scoped URL a recommended/fallback route; missing or unconfigured preferences remain unknown. A different country/stack remains inapplicable. No replacement URL is guessed, no CV location/technology is inferred, and applicability proves neither qualification, work eligibility nor execution permission. CLI source selection reads current private settings; direct callers can supply `profile` explicitly. All planning still has `executes_network: false`.
